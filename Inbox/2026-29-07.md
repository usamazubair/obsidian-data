## 1. Create the Run ID

```
RUN_ID="manual-$(date +%Y%m%d-%H%M%S)"
echo "$RUN_ID"
```

Example:

```
manual-20260729-121500
```

## 2. Define the deployment directories

```
BASE_DIR="/home/ubuntu/ebm-route-deployments"
RUN_DIR="$BASE_DIR/runs/$RUN_ID"
STATUS_FILE="$RUN_DIR/status.json"
```

Create the run directory:

```
mkdir -p "$RUN_DIR"
```

## 3. Export the variables required by the script

```
export EBM_RUN_DIR="$RUN_DIR"
export EBM_STATUS_FILE="$STATUS_FILE"
export EBM_DEPLOY_BASE_DIR="$BASE_DIR"
```

Verify them:

```
echo "RUN_ID=$RUN_ID"
echo "EBM_RUN_DIR=$EBM_RUN_DIR"
echo "EBM_STATUS_FILE=$EBM_STATUS_FILE"
echo "EBM_DEPLOY_BASE_DIR=$EBM_DEPLOY_BASE_DIR"
```

## 4. Run the generation script

From your current `scripts` directory:

```
bash ./generate-ebm-routes.sh "$RUN_ID"
```

Do not run:

```
sudo -n bash generate-ebm-routes.sh
```





Use the **same `RUN_ID`** that you used while generating the routes.

## 1. Find your generated Run ID

List the recent runs:

```
ls -lt /home/ubuntu/ebm-route-deployments/runs
```

For example:

```
manual-20260729-171500
```

Set it:

```
RUN_ID="manual-20260729-171500"
```

Do not create a new Run ID for pushing. Use the generation Run ID so the same status file and logs remain linked.

## 2. Set the base and status paths

```
BASE_DIR="/home/ubuntu/ebm-route-deployments"
RUN_DIR="$BASE_DIR/runs/$RUN_ID"
STATUS_FILE="$RUN_DIR/status.json"

export EBM_DEPLOY_BASE_DIR="$BASE_DIR"
export EBM_RUN_DIR="$RUN_DIR"
export EBM_STATUS_FILE="$STATUS_FILE"
```

Verify:

```
echo "RUN_ID=$RUN_ID"
echo "RUN_DIR=$EBM_RUN_DIR"
echo "STATUS_FILE=$EBM_STATUS_FILE"
```

## 3. Confirm the generated ZIP exists

Your push script uses this fixed path:

```
/home/ubuntu/ebm-route-deployments/latest/ebm_routes_latest.zip
```

Check it:

```
ls -lh "$BASE_DIR/latest/ebm_routes_latest.zip"
```

Test the ZIP:

```
unzip -t "$BASE_DIR/latest/ebm_routes_latest.zip"
```

Do not continue if the ZIP is missing or corrupted.

## 4. Set production server details

Set the production public/private host reachable from this machine:

```
export PRODUCTION_DEPLOY_HOST="YOUR_PRODUCTION_EC2_IP"
export PRODUCTION_DEPLOY_USER="ubuntu"
export PRODUCTION_DEPLOY_PORT="22"
```

For example:

```
export PRODUCTION_DEPLOY_HOST="54.169.27.236"
export PRODUCTION_DEPLOY_USER="ubuntu"
export PRODUCTION_DEPLOY_PORT="22"
```

Set the production EBM destination:

```
export PRODUCTION_EBM_DATA_PATH="/home/ubuntu/sa-gtm-backend/data/EBM"
```

## 5. Set the production password safely

Do not type the password directly inside the command because it will remain in shell history.

Use:

```
read -s -p "Production SSH password: " PRODUCTION_DEPLOY_PASSWORD
echo
export PRODUCTION_DEPLOY_PASSWORD
```

Verify only that it exists, without displaying it:

```
if [ -n "${PRODUCTION_DEPLOY_PASSWORD:-}" ]; then
    echo "Production password is configured."
else
    echo "Production password is missing."
fi
```

## 6. Check whether `sshpass` is installed

Because your script requires `PRODUCTION_DEPLOY_PASSWORD`, it likely uses `sshpass`.

Check:

```
command -v sshpass
```

If nothing is returned, install it according to your EC2 operating system.

For Amazon Linux/RHEL:

```
sudo yum install -y sshpass
```

Or:

```
sudo dnf install -y sshpass
```

For Ubuntu:

```
sudo apt-get update
sudo apt-get install -y sshpass
```

## 7. Test SSH before deploying

Test the credentials separately:

```
sshpass -p "$PRODUCTION_DEPLOY_PASSWORD" \
ssh \
  -p "$PRODUCTION_DEPLOY_PORT" \
  -o StrictHostKeyChecking=accept-new \
  "$PRODUCTION_DEPLOY_USER@$PRODUCTION_DEPLOY_HOST" \
  "echo Connected && whoami && hostname"
```

Expected output:

```
Connected
ubuntu
ip-...
```

If this fails, do not run the push script yet.

## 8. Run `push-ebm-routes.sh`

You are already logged in as root, so run:

```
bash ./push-ebm-routes.sh "$RUN_ID" production
```

The second argument must be:

```
production
```

This script currently does not support staging:

```
bash ./push-ebm-routes.sh "$RUN_ID" staging
```

would produce:

```
This script currently supports production only.
```

## 9. Check the result

Immediately check the exit code:

```
echo $?
```

Success:

```
0
```

Check the status file:

```
cat "$STATUS_FILE"
```

For readable JSON:

```
python3 -m json.tool "$STATUS_FILE"
```

Check whether the push lock remains:

```
lslocks | grep push-ebm-production
```

If the deployment has finished, there should be no active lock holder.

## 10. Verify on production EC2

Connect to production:

```
ssh ubuntu@"$PRODUCTION_DEPLOY_HOST"
```

Check the EBM directory:

```
ls -lh /home/ubuntu/sa-gtm-backend/data/EBM
```

Check city directories:

```
find /home/ubuntu/sa-gtm-backend/data/EBM \
  -mindepth 1 \
  -maxdepth 1 \
  -type d \
  | sort
```

Check route files:

```
find /home/ubuntu/sa-gtm-backend/data/EBM \
  -type f \
  -name 'route.json' \
  | head -20
```

Confirm compressed files do not remain:

```
find /home/ubuntu/sa-gtm-backend/data/EBM \
  -type f \
  \( -name '*.gz' -o -name '*.gnz' \) \
  | head
```

Expected: no output.

## 11. Remove the password from the shell

After deployment:

```
unset PRODUCTION_DEPLOY_PASSWORD
```

## Complete copy-paste sequence

Replace the Run ID, host, and password when prompted:

```
cd /path/to/scripts

RUN_ID="manual-20260729-171500"

BASE_DIR="/home/ubuntu/ebm-route-deployments"
RUN_DIR="$BASE_DIR/runs/$RUN_ID"
STATUS_FILE="$RUN_DIR/status.json"

export EBM_DEPLOY_BASE_DIR="$BASE_DIR"
export EBM_RUN_DIR="$RUN_DIR"
export EBM_STATUS_FILE="$STATUS_FILE"

export PRODUCTION_DEPLOY_HOST="YOUR_PRODUCTION_EC2_IP"
export PRODUCTION_DEPLOY_USER="ubuntu"
export PRODUCTION_DEPLOY_PORT="22"
export PRODUCTION_EBM_DATA_PATH="/home/ubuntu/sa-gtm-backend/data/EBM"

read -s -p "Production SSH password: " PRODUCTION_DEPLOY_PASSWORD
echo
export PRODUCTION_DEPLOY_PASSWORD

echo "Checking generated ZIP..."
ls -lh "$BASE_DIR/latest/ebm_routes_latest.zip"
unzip -t "$BASE_DIR/latest/ebm_routes_latest.zip"

echo "Testing production SSH..."
sshpass -p "$PRODUCTION_DEPLOY_PASSWORD" \
ssh \
  -p "$PRODUCTION_DEPLOY_PORT" \
  -o StrictHostKeyChecking=accept-new \
  "$PRODUCTION_DEPLOY_USER@$PRODUCTION_DEPLOY_HOST" \
  "echo Connected && whoami && hostname"

echo "Starting production push..."
bash ./push-ebm-routes.sh "$RUN_ID" production

EXIT_CODE=$?

echo "Push exit code: $EXIT_CODE"

if [ -f "$STATUS_FILE" ]; then
    python3 -m json.tool "$STATUS_FILE"
fi

unset PRODUCTION_DEPLOY_PASSWORD

exit "$EXIT_CODE"
```
