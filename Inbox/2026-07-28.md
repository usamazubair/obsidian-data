# Final deployment flow

```
Development:
Push development
→ automatic development deployment

Production:
Merge code into master
→ manually run deploy-production
→ production EC2 updates
→ build
→ PM2 restart
```

A manually triggered custom pipeline is safer for production because pushing or merging to `master` does not immediately restart the live application. Bitbucket supports custom pipelines that you run manually against a selected branch or commit.

# Step 5: Create the production deployment script

Create the directory:

```
sudo mkdir -p /home/ubuntu/deployProduction
```

Create the script:

```
sudo nano /home/ubuntu/deployProduction/deploy-tm-production.sh
```

Paste this complete script:

```
#!/usr/bin/env bash

set -Eeuo pipefail

APP_DIR="/home/ubuntu/sa-gtm-backend"
BRANCH="master"
NODE_VERSION="16.20.2"
PM2_APP_NAME="tm-backend"
LOCK_FILE="/var/lock/tm-production-deployment.lock"

echo "=========================================="
echo "TM BACKEND PRODUCTION DEPLOYMENT"
echo "User: $(whoami)"
echo "Branch: $BRANCH"
echo "Directory: $APP_DIR"
echo "Started: $(date)"
echo "=========================================="

# ---------------------------------------------------------
# 1. Ensure deployment runs as root
# ---------------------------------------------------------

if [ "$(id -u)" -ne 0 ]; then
    echo "ERROR: This deployment must run as root."
    exit 1
fi

export HOME="/root"
export NVM_DIR="/root/.nvm"

# ---------------------------------------------------------
# 2. Prevent overlapping production deployments
# ---------------------------------------------------------

exec 9>"$LOCK_FILE"

if ! flock -n 9; then
    echo "ERROR: Another production deployment is already running."
    exit 1
fi

# ---------------------------------------------------------
# 3. Validate project
# ---------------------------------------------------------

if [ ! -d "$APP_DIR" ]; then
    echo "ERROR: Project directory does not exist:"
    echo "$APP_DIR"
    exit 1
fi

if [ ! -d "$APP_DIR/.git" ]; then
    echo "ERROR: Directory is not a Git repository:"
    echo "$APP_DIR"
    exit 1
fi

# ---------------------------------------------------------
# 4. Trust repository for root
# ---------------------------------------------------------

if ! git config --global --get-all safe.directory 2>/dev/null |
    grep -Fxq "$APP_DIR"; then
    echo "Adding Git safe directory..."
    git config --global --add safe.directory "$APP_DIR"
fi

# ---------------------------------------------------------
# 5. Load NVM
# ---------------------------------------------------------

if [ ! -s "$NVM_DIR/nvm.sh" ]; then
    echo "ERROR: Root NVM was not found at:"
    echo "$NVM_DIR/nvm.sh"
    exit 1
fi

# shellcheck disable=SC1090
source "$NVM_DIR/nvm.sh"

if ! nvm ls "$NODE_VERSION" >/dev/null 2>&1; then
    echo "ERROR: Node.js $NODE_VERSION is not installed for root."
    exit 1
fi

echo "Selecting Node.js $NODE_VERSION..."
nvm use "$NODE_VERSION"

echo "Node version: $(node -v)"
echo "NPM version: $(npm -v)"

if ! command -v pm2 >/dev/null 2>&1; then
    echo "ERROR: PM2 is unavailable under Node.js $NODE_VERSION."
    exit 1
fi

# ---------------------------------------------------------
# 6. Fetch production code
# ---------------------------------------------------------

cd "$APP_DIR"

PREVIOUS_COMMIT="$(git rev-parse HEAD)"

echo "Previous commit:"
git log -1 --oneline

echo "Fetching origin/$BRANCH..."
git fetch origin "$BRANCH"

echo "Switching to $BRANCH..."
git checkout "$BRANCH"

echo "Resetting local code to origin/$BRANCH..."
git reset --hard "origin/$BRANCH"

CURRENT_COMMIT="$(git rev-parse HEAD)"

echo "Current production commit:"
git log -1 --oneline

if [ "$PREVIOUS_COMMIT" = "$CURRENT_COMMIT" ]; then
    echo "Notice: Production is already on this commit."
fi

# ---------------------------------------------------------
# 7. Fix build permissions
# ---------------------------------------------------------

chown -R root:root "$APP_DIR"
chmod -R u+rwX "$APP_DIR"

if [ -d "$APP_DIR/dist" ]; then
    echo "Cleaning previous build..."
    chattr -R -i "$APP_DIR/dist" 2>/dev/null || true
    rm -rf "$APP_DIR/dist"
fi

# ---------------------------------------------------------
# 8. Install dependencies
# ---------------------------------------------------------

echo "Installing production dependencies..."

npm install \
    --legacy-peer-deps \
    --no-audit \
    --no-fund

# ---------------------------------------------------------
# 9. Build NestJS application
# ---------------------------------------------------------

echo "Building NestJS application..."

npm run build

if [ ! -d "$APP_DIR/dist" ]; then
    echo "ERROR: dist directory was not created."
    exit 1
fi

if [ ! -f "$APP_DIR/dist/main.js" ]; then
    echo "ERROR: dist/main.js was not created."
    exit 1
fi

# ---------------------------------------------------------
# 10. Restart production PM2 process
# ---------------------------------------------------------

if ! pm2 describe "$PM2_APP_NAME" >/dev/null 2>&1; then
    echo "ERROR: Root PM2 process '$PM2_APP_NAME' was not found."
    pm2 list
    exit 1
fi

echo "Restarting production PM2 process: $PM2_APP_NAME..."

pm2 restart "$PM2_APP_NAME" --update-env

echo "Saving root PM2 process list..."
pm2 save

echo "Production PM2 status:"
pm2 status "$PM2_APP_NAME"

# ---------------------------------------------------------
# 11. Summary
# ---------------------------------------------------------

echo "=========================================="
echo "PRODUCTION DEPLOYMENT COMPLETED"
echo "Branch: $BRANCH"
echo "Previous commit: ${PREVIOUS_COMMIT:0:8}"
echo "Current commit: ${CURRENT_COMMIT:0:8}"
echo "Node: $(node -v)"
echo "PM2 application: $PM2_APP_NAME"
echo "Completed: $(date)"
echo "=========================================="
```

Your Development environment should separately contain:

EC2_USER = ubuntu

This prevents one shared repository-level `EC2_HOST` from pointing both pipelines to the same machine.

# Step 12: Use the complete two-environment pipeline

Replace your `bitbucket-pipelines.yml` with:

```
image: atlassian/default-image:4

pipelines:
  branches:
    development:
      - step:
          name: Deploy Development to EC2
          deployment: Development
          script:
            - test -n "$EC2_HOST"
            - test -n "$EC2_USER"

            - echo "Deploying development commit ${BITBUCKET_COMMIT}..."

            - >
              ssh
              -o BatchMode=yes
              -o ConnectTimeout=20
              -o ServerAliveInterval=30
              -o ServerAliveCountMax=4
              "${EC2_USER}@${EC2_HOST}"
              "sudo -n /home/ubuntu/deployDevelopment/deploy-tm-development.sh"

  custom:
    deploy-production:
      - step:
          name: Deploy Production to EC2
          deployment: Production
          script:
            - test -n "$EC2_HOST"
            - test -n "$EC2_USER"

            - |
              if [ "${BITBUCKET_BRANCH}" != "master" ]; then
                echo "ERROR: Production deployment must run from master."
                echo "Selected branch: ${BITBUCKET_BRANCH}"
                exit 1
              fi

            - echo "Deploying production commit ${BITBUCKET_COMMIT}..."

            - >
              ssh
              -o BatchMode=yes
              -o ConnectTimeout=20
              -o ServerAliveInterval=30
              -o ServerAliveCountMax=4
              "${EC2_USER}@${EC2_HOST}"
              "sudo -n /home/ubuntu/deployProduction/deploy-tm-production.sh"
```

The production branch guard prevents someone from accidentally selecting `development` while manually starting the production pipeline.

A custom pipeline must exist in the `bitbucket-pipelines.yml` file on the branch selected when starting it. Therefore, this YAML must also be merged into `master` before `deploy-production` can be selected for the `master` branch.

# Optional: automatic production deployment

To automatically deploy whenever `master` is pushed, replace the `custom` production section with:

```
  branches:
    development:
      - step:
          name: Deploy Development to EC2
          deployment: Development
          script:
            - test -n "$EC2_HOST"
            - test -n "$EC2_USER"
            - >
              ssh
              -o BatchMode=yes
              -o ConnectTimeout=20
              "${EC2_USER}@${EC2_HOST}"
              "sudo -n /home/ubuntu/deployDevelopment/deploy-tm-development.sh"

    master:
      - step:
          name: Deploy Production to EC2
          deployment: Production
          script:
            - test -n "$EC2_HOST"
            - test -n "$EC2_USER"
            - >
              ssh
              -o BatchMode=yes
              -o ConnectTimeout=20
              "${EC2_USER}@${EC2_HOST}"
              "sudo -n /home/ubuntu/deployProduction/deploy-tm-production.sh"
```

The recommended arrangement remains:

```
development → automatic
production → manual from master
```
